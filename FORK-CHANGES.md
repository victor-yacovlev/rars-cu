# Список изменений

  - [x] Возможность спрашивать аргументы первой функции у пользователя, если отсутствует `main` или `_start`
    - Если в глобальной таблице символов нет `main` и `_start`, точкой входа считается первая (по порядку возникновения в коде) функция из таблицы символов
    - Перед запуском отображается модальное диалоговое окно для ввода целочисленных аргументов функции. Значения записываются в регистры `a0`–`a7` в соответствии с соглашением о вызовах RISC-V; лишние аргументы кладутся на стек
    - Если строкой непосредственно перед меткой функции идёт комментарий (`#` или `//`) с Си-сигнатурой функции (например, `# int64_t poly(int64_t a, int64_t b)`), в диалоге запрашиваются все именованные параметры в фиксированном количестве. Пока все параметры не введены, запуск не выполняется
    - Фокус ввода в диалоге сразу устанавливается в поле первого аргумента (текст в поле выделяется)
    - При повторном запуске поля диалога заполняются значениями предыдущего запуска; в диалоге без сигнатуры аналогично предлагается последняя введённая строка аргументов. История аргументов хранится в настройках (`java.util.prefs`, класс `rars/venus/FunctionArgumentsPersistence.java`) и уникальна для каждого открытого файла — ключом служит путь открытого файла
    - Регистр `ra` устанавливается на служебный адрес возврата, поэтому инструкция `ret` корректно завершает выполнение (без ошибки `Instruction load access error`). Проверка достижения адреса возврата выполняется до проверки лимита шагов, поэтому при пошаговом выполнении `ret` завершает программу за один шаг
    - Тип возвращаемого значения при отсутствии сигнатуры по умолчанию считается целочисленным (не `void`)
    - Если сигнатура отсутствует или имеет возвращаемое значение (не `void`), после выполнения в окно `Run I/O` выводится строка вида: `Execution Done: poly(A, B, C, D, X) = RET` (результат берётся из `a0`); для сигнатуры с `void` результат не выводится
  - [x] Возможность использовать токен `//` (как в gcc) в качестве комментария, в дополнение к токену `#`
    - Токенизатор распознаёт `//` как начало комментария до конца строки; одиночный символ `/` комментарием не считается
    - Подсветка синтаксиса в редакторе также окрашивает `//`-комментарии
  - [x] Отображение регистров одновременнов в hex и десятичном виде
    - В таблицах «Registers» и «Control and Status» целочисленный столбец «Value» заменён на три столбца: «Value (Signed)» (знаковое десятичное), «Value (Unsigned)» (беззнаковое десятичное) и «Value (HEX)» (шестнадцатеричное)
    - При изменении значений эмулятором обновляются все три представления
    - Редактирование любого из представлений обновляет регистр и остальные представления; в беззнаковом столбце принимаются значения за пределами знакового диапазона (напр., 4294967295)
    - Удалён пункт меню «Settings» → «Values displayed in hexadecimal», поскольку все представления отображаются всегда
  - [x] В режиме выполнения по шагам нужно в текстовом редакторе (вкладка "Edit") подсвечивать ту строку, которая будет выполнена при выполнении очередного шага
    - При пошаговом выполнении, паузе на брейкпоинте и откате шага (Backstep) в редакторе (вкладка «Edit») строка исходного кода, соответствующая текущему счётчику команд (инструкции, которая будет выполнена следующей), подсвечивается фоном под текстом — это отдельная UI-операция, не связанная с выделением текста. Если выполнение ещё не началось (Assemble/Reset) или уже завершилось (статус TERMINATED), подсветка не показывается (снимается)
    - `VenusUI.highlightStep(int address)` подсвечивает инструкцию в окне Text Segment (вкладка «Execute»), `VenusUI.highlightStepSourceLine(int address)` — в редакторе исходного кода (сопоставление адрес → строка через `ProgramStatement.getAddress()/getSourceLine()/getSourceFile()`), `VenusUI.clearHighlightedLines()` снимает подсветку перед началом и после завершения выполнения
    - В интерфейс `TextEditingArea` добавлен `setHighlightedLine(int)`; в `GenericTextArea` рисуется полноширинная фоновая заливка строки через `Highlighter`, в `JEditBasedTextArea` — через `TextAreaPainter.setExecutionLine`; выделение текста при этом не изменяется
    - Если инструкция не соответствует строке открытого файла, подсветка не выполняется
    - Первое нажатие Step (F7), когда программа ещё не запущена, переводит её в состояние «Prepare»: запрашивает аргументы и подсвечивает первую строку, которая будет выполнена, не выполняя ни одной инструкции; последующие нажатия F7 выполняют очередную строку
  - [x] Изменена иерархия вкладок: верхний уровень — открытые файлы, второй уровень — подвкладки «Edit»/«Memory» внутри каждого файла (раньше верхним уровнем были «Edit»/«Memory», а файлы — вторым)
    - Каждая вкладка файла — `FileViewPane` (подвкладки Edit и Memory); верхний уровень — `EditTabbedPane` (файлы), `MainPane` стал обычным контейнером файлового уровня
    - Окно памяти (ExecutePane) остаётся синглтоном и «переезжает» в подвкладку «Memory» того файла, где она открыта (`MainPane.attachMemoryView`); при переключении на файл с открытой подвкладкой «Memory» вид перемещается туда без пересборки
    - Логика подвкладки «Memory» прежняя: при её выборе — принудительная сборка текущего файла, при ошибке — возврат на «Edit», перекомпоновка окон после сборки; во время сессии выполнения показывается живое состояние без пересборки
    - Все ранее реализованные сценарии (per-file проекты, блокировки на время выполнения, серые недоступные вкладки файлов) работают на новом верхнем уровне
  - [x] Сохранение положения и размера GUI-окна и восстановление при запуске. Также сохраняется и восстанавливается расположение отдельных UI-элементов. При восстановлении Layout окна необходимо поддерживать минимально разумные размеры контролов, чтобы окна и элементы не были пустыми
    - Сохраняются: геометрия окна (позиция/размер в немаксимизированном состоянии + флаг максимизации), положения разделителей сплиттеров (основной вертикальный и регистровый горизонтальный), выбранная вкладка Registers, границы внутренних фреймов Execute-панели (Text/Data Segment, Labels)
    - Хранение — `java.util.prefs` (как у остальных настроек), класс `rars/venus/UiLayoutPersistence.java`; сохранение — при выходе через кнопку «X» и меню File → Exit, восстановление — при старте (`VenusUI`) и при первом открытии вкладки Execute (`ExecutePane.applyPersistedWindowBounds`)
    - Минимальные разумные размеры: ограничен минимальный размер главного окна (600×400), позиции разделителей клампятся так, чтобы обе стороны оставались ≥ 80 px; границы внутренних фреймов клампятся в видимую область с минимумом 200×100
    - Если сохранённой геометрии нет — прежнее поведение (запуск на весь экран)
    - Геометрия, сохранённая на другом мониторе/разрешении, не применяется, если окно не пересекается ни с одним экраном
 - [x] Запоминается каталог для диалоговых окон открытия и сохранения файлов
    - Каталоги последних операций Open и Save сохраняются между запусками и восстанавливаются при старте
    - Хранение — `java.util.prefs` (как у остальных настроек), класс `rars/venus/FileDirectoryPersistence.java`; сохранение — при выборе файла в диалоге, восстановление — при создании `Editor`
    - Если сохранённый каталог больше не существует или не является каталогом, используется каталог запуска
 - [x] Элементы "Messages" и "Run I/O" отображаются рядом слева направо, а не вкладками. Кнопка "Clear" удалена из интерфейса, так как занимает слишком много места. Функционал кнопки "Clear" перенесен в контекстное меню на соответствующем окне
    - `MessagesPane` теперь горизонтальный `JSplitPane`: сообщения ассемблера слева, ввод-вывод программы справа, с регулируемым разделителем
    - Кнопки «Clear» удалены из интерфейса; очистка доступна через контекстное меню (правый клик) соответствующей области
    - Заголовки «Messages» и «Run I/O» сохранены как подписи над областями
 - [x] При открытии текстового файла он по умолчанию открывается в режиме "Edit", а не "Execute"
    - Операция Open всегда переключает главную панель на вкладку «Edit», в том числе если файл уже открыт, а пользователь находится на вкладке «Execute»
    - Даже при включённой настройке «Assemble on open» (которая автоматически собирает файл и переключает на вкладку «Execute») после открытия приложение остаётся на вкладке «Edit»
 - [x] После выполения программы до конца действия Step (F7) и Go (F5) должны быть доступны, и перед запуском программы сбрасывать состояние - выполнять действие Reset (F12)
    - После завершения выполнения программы (статус TERMINATED) кнопки и пункты меню Step (F7) и Go (F5) остаются доступными
    - Логика сброса вынесена из `RunResetAction` в переиспользуемый статический метод `RunResetAction.performReset(VenusUI)`
    - Если программа завершилась и пользователь нажимает Step или Go, перед запуском автоматически выполняется Reset (сброс регистров/памяти/состояния и повторная сборка), затем запуск идёт с начала
  - [x] Действия Go (F5) и Step (F7) доступны во время редактирования (статусы EDITED/NOT_EDITED) и автоматически запускают ассемблирование перед запуском
    - При нажатии F5/F7, если файл ещё не собран или был отредактирован после последней сборки, сначала автоматически выполняется Assemble (с автосохранением при EDITED); при ошибке сборки запуск отменяется (ошибки выводятся как обычно), кнопки остаются доступными
    - Реализация: пролог в `RunGoAction`/`RunStepAction` вызывает действие Assemble и проверяет успех; `setMenuStateEditing`/`setMenuStateNotEdited` включают Go/Step
    - При редактировании собранного файла статический флаг `FileStatus.assembled` синхронно сбрасывается вместе с пер-файловым состоянием
  - [x] После ассемблирования не выполняется переключение на вкладку «Execute»
    - Цель ассемблирования (F3) — диагностика ошибок в программе: пользователь остаётся во вкладке «Edit», ошибки/предупреждения выводятся в панель Messages (с переходом к строке ошибки в редакторе); окно Execute заполняется как обычно и открывается вручную при необходимости
  - [x] Вкладка «Execute» переименована в «Memory» с новой семантикой: просмотр памяти и регистров собранной программы
    - При переключении на вкладку «Memory» принудительно выполняется ассемблирование текущего файла — вкладка всегда показывает состояние, соответствующее текущему тексту программы (регистры и память — в состоянии сразу после сборки)
    - Во время активной сессии выполнения (Go/Step/пауза) переключение на «Memory» не вызывает пересборку — показывается живое состояние выполнения
    - При ошибке сборки или отсутствии открытого файла пользователь возвращается на вкладку «Edit» (ошибки — в панели Messages, с переходом к строке ошибки в редакторе)
    - После принудительной сборки окна внутри Memory перекомпоновываются: Text Segment гарантированно видим и занимает достаточный размер
  - [x] Действие Stop (F11) всегда доступно во время выполнения программы и принудительно его завершает
    - Если поток симуляции активен (запуск Go) — поведение прежнее: поток прерывается, очистку выполняет `RunGoAction.stopped`
    - Если поток симуляции не активен, но сессия выполнения активна (пошаговый режим между инструкциями, состояние Prepare, приостановленная программа) — прямой путь `RunStopAction.forceTerminate`: статус TERMINATED (следующий Go/Step автоматически делает Reset), сессия выполнения завершается (разблокируются редактирование и переключение вкладок), выводятся финальные значения регистров/памяти. Заодно исправлено: раньше Stop после паузы (F9) не работал
    - Доступность Stop вычисляется централизованно: `VenusUI.updateStopActionEnabled()` — включён при активной сессии выполнения или работающем потоке симуляции, иначе выключен
  - [x] Каждый открытый файл считается отдельным независимым проектом и выполняется по-отдельности (исправлен баг: после открытия двух файлов и переключения на предыдущую вкладку действия выполнения становились неактивными)
    - Состояние «собранной программы» хранится для каждого файла (вкладки) отдельно: `EditPane` хранит собранную `RISCVprogram`, список собранных единиц трансляции и флаги ассемблера (`setAssemblyState`/`clearAssemblyState`), а также собственный статус в своём `FileStatus` (в т.ч. пер-файловый флаг `assembled`)
    - Статус меню (доступность Assemble/Go/Step/Reset и т.д.) при переключении вкладок восстанавливается из статуса выбранного файла: у собранного ранее файла действия выполнения остаются доступными
    - При переключении на вкладку файла, чья программа не загружена в общем состоянии симулятора (память/регистры/окно Execute — синглтоны), его проект восстанавливается: программа пересобирается из сохранённых единиц, память и регистры сбрасываются, окно Execute обновляется (`EditTabbedPane.activateProject`/`reloadProject`). Промежуточное состояние выполнения (например, останов посреди отладки) при этом не сохраняется — проект стартует с чистого состояния
    - Одновременно выполняться может только одна программа: пока идёт выполнение (Go), переключение на другую вкладку заблокировано — выбор возвращается на вкладку выполняемой программы (`Simulator.isSimulating()`); режим «Assemble all files in directory» сохраняет прежнее поведение
    - Во время выполнения программы в UI блокируются: редактирование текста выполняемой программы (текст делается read-only — `EditTabbedPane.beginRunSession/endRunSession`) и переключение на другие открытые вкладки. Сессия выполнения начинается с первого нажатия Go (F5) или Step (F7, включая состояние Prepare до первой инструкции) и заканчивается при завершении (нормальное завершение, Stop, ошибка, лимит шагов), а также по Reset (F12) или повторной сборке Assemble (F3); пауза (F9) сессию не завершает. Если изменение текста всё же произошло (защитный сценарий), сессия корректно завершается — программа не остаётся в неуправляемом состоянии, для повторного запуска требуется пересборка
    - Отключённый во время сессии функционал визуализируется: действия Cut/Paste/Find-Replace (меню и тулбар) переводятся в disabled (`VenusUI.updateEditActionsEnabled()`; Undo/Redo отключены и ранее); вкладки других программ — disabled/серые, клик по ним не переключает (`EditTabbedPane.updateTabAppearance`, `setEnabledAt`); фон read-only текста становится светло-серым, незначительно отличающимся от обычного (для белого фона — #F2F2F2; `TextEditingArea.readOnlyBackground`). Немодифицирующие действия Copy и Select All остаются доступными
    - Заблокированный редактор дополнительно не подсвечивает текущую строку с курсором и не даёт выделять текст/перемещать курсор: `TextEditingArea.setLocked(true)` скрывает каретку и отключает подсветку строки (с восстановлением из настроек при разблокировке), редактор теряет фокусируемость (клавиатурное перемещение курсора невозможно), а события мыши и клавиатуры перехватываются (клик/драг не перемещают каретку и не выделяют текст; прокрутка колесом и скроллбарами работает)
    - Редактирование файла инвалидирует его собранную программу (статус → EDITED, действия выполнения недоступны до повторной сборки)
    - `RunResetAction.performReset` пересобирает программу проекта текущего файла (использует сохранённые для вкладки входные данные ассемблера)
  - [x] Улучшено поле номеров строк в редакторе
    - Номера строк отображаются всегда; чекбокс «Show Line Numbers» удалён из нижней панели редактора (настройка `EditorLineNumbersDisplayed` больше не используется)
    - Справа от блока номеров рисуется вертикальная линия-разделитель
    - Блок номеров рисуется тем же светло-серым фоном, который используется для заблокированного (read-only) редактора (`TextEditingArea.readOnlyBackground`), и обновляется при смене настроек шрифта/цветов

    - Клик по номеру строки устанавливает точку останова, если строка исполняемая (генерирует инструкции); повторный клик по строке с установленной точкой - снимает её; клик по неисполняемой строке ничего не делает
    - Точки останова возможны только в редакторе файла текущего загруженного проекта и только когда программа не выполняется (во время сессии выполнения поле номеров не реагирует)
    - Двусторонняя синхронизация с чекбоксами столбца Bkpt окна Text Segment: клик в редакторе обновляет чекбоксы всех инструкций строки; изменение чекбоксов (включая Clear all breakpoints и пересборку, сбрасывающую точки) обновляет маркеры в полях редакторов (`TextSegmentWindow.setBreakpointsChangedCallback`, callback через `VenusUI` для всех открытых редакторов)
