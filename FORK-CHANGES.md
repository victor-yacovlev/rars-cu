# Список изменений


## Функциональные изменения в форке по сравнению с оригинальным проектом

  - [x] Возможность спрашивать аргументы первой функции у пользователя, если отсутствует `main` или `_start`
    - Если в глобальной таблице символов нет `main` и `_start`, точкой входа считается первая (по порядку возникновения в коде) функция из таблицы символов
    - Перед запуском отображается модальное диалоговое окно для ввода целочисленных аргументов функции. Значения записываются в регистры `a0`–`a7` в соответствии с соглашением о вызовах RISC-V; лишние аргументы кладутся на стек
    - Если строкой непосредственно перед меткой функции идёт комментарий (`#` или `//`) с Си-сигнатурой функции (например, `# int64_t poly(int64_t a, int64_t b)`), в диалоге запрашиваются все именованные параметры в фиксированном количестве. Пока все параметры не введены, запуск не выполняется
    - Регистр `ra` устанавливается на служебный адрес возврата, поэтому инструкция `ret` корректно завершает выполнение (без ошибки `Instruction load access error`). Проверка достижения адреса возврата выполняется до проверки лимита шагов, поэтому при пошаговом выполнении `ret` завершает программу за один шаг
    - Если сигнатура функции имеет возвращаемое значение (не `void`), после выполнения в окно `Messages` выводится строка вида: `Execution Done: poly(A, B, C, D, X) = RET`
  - [x] Возможность использовать токен `//` (как в gcc) в качестве комментария, в дополнение к токену `#`
    - Токенизатор распознаёт `//` как начало комментария до конца строки; одиночный символ `/` комментарием не считается
    - Подсветка синтаксиса в редакторе также окрашивает `//`-комментарии
  - [x] Отображение регистров одновременнов в hex и десятичном виде
    - В таблицах «Registers» и «Control and Status» целочисленный столбец «Value» заменён на три столбца: «Value (Signed)» (знаковое десятичное), «Value (Unsigned)» (беззнаковое десятичное) и «Value (HEX)» (шестнадцатеричное)
    - При изменении значений эмулятором обновляются все три представления
    - Редактирование любого из представлений обновляет регистр и остальные представления; в беззнаковом столбце принимаются значения за пределами знакового диапазона (напр., 4294967295)
    - Удалён пункт меню «Settings» → «Values displayed in hexadecimal», поскольку все представления отображаются всегда
  - [x] В режиме выполнения по шагам нужно в текстовом редакторе (вкладка "Edit") подсвечивать ту строку, которая будет выполнена при выполнении очередного шага
    - При пошаговом выполнении, паузе на брейкпоинте и откате шага (Backstep) в редакторе (вкладка «Edit») строка исходного кода, соответствующая текущему счётчику команд (инструкции, которая будет выполнена следующей), подсвечивается фоном под текстом — это отдельная UI-операция, не связанная с выделением текста. Если выполнение ещё не началось (Assemble/Reset) или уже завершилось (статус TERMINATED), подсветка не показывается (снимается)
    - `VenusUI.highlightStep(int address)` подсвечивает инструкцию в окне Text Segment (вкладка «Execute»), `VenusUI.highlightStepSourceLine(int address)` — в редакторе исходного кода (сопоставление адрес → строка через `ProgramStatement.getAddress()/getSourceLine()/getSourceFile()`), `VenusUI.clearHighlightedLines()` снимает подсветку перед началом и после завершения выполнения
    - В интерфейс `TextEditingArea` добавлен `setHighlightedLine(int)`; в `GenericTextArea` рисуется полноширинная фоновая заливка строки через `Highlighter`, в `JEditBasedTextArea` — через `TextAreaPainter.setExecutionLine`; выделение текста при этом не изменяется
    - Если инструкция не соответствует строке открытого файла, подсветка не выполняется
    - Первое нажатие Step (F7), когда программа ещё не запущена, переводит её в состояние «Prepare»: запрашивает аргументы и подсвечивает первую строку, которая будет выполнена, не выполняя ни одной инструкции; последующие нажатия F7 выполняют очередную строку


## Улучшения UI
  - [x] Сохранение положения и размера GUI-окна и восстановление при запуске. Также сохраняется и восстанавливается расположение отдельных UI-элементов. При восстановлении Layout окна необходимо поддерживать минимально разумные размеры контролов, чтобы окна и элементы не были пустыми
    - Сохраняются: геометрия окна (позиция/размер в немаксимизированном состоянии + флаг максимизации), положения разделителей сплиттеров (основной вертикальный и регистровый горизонтальный), выбранная вкладка Registers, границы внутренних фреймов Execute-панели (Text/Data Segment, Labels)
    - Хранение — `java.util.prefs` (как у остальных настроек), класс `rars/venus/UiLayoutPersistence.java`; сохранение — при выходе через кнопку «X» и меню File → Exit, восстановление — при старте (`VenusUI`) и при первом открытии вкладки Execute (`ExecutePane.applyPersistedWindowBounds`)
    - Минимальные разумные размеры: ограничен минимальный размер главного окна (600×400), позиции разделителей клампятся так, чтобы обе стороны оставались ≥ 80 px; границы внутренних фреймов клампятся в видимую область с минимумом 200×100
    - Если сохранённой геометрии нет — прежнее поведение (запуск на весь экран)
    - Геометрия, сохранённая на другом мониторе/разрешении, не применяется, если окно не пересекается ни с одним экраном
 - [x] Запоминается каталог для диалоговых окон открытия и сохранения файлов
    - Каталоги последних операций Open и Save сохраняются между запусками и восстанавливаются при старте
    - Хранение — `java.util.prefs` (как у остальных настроек), класс `rars/venus/FileDirectoryPersistence.java`; сохранение — при выборе файла в диалоге, восстановление — при создании `Editor`
    - Если сохранённый каталог больше не существует или не является каталогом, используется каталог запуска
 - [x] Элементы "Messages" и "Run I/O" отображаются рядом слева направо, а не вкладками. Кнопка "Clear" удалена из интерфейса, так как занимает слишком много места. Функционал кнопки "Clear" перенесен в контекстное меню на соответствующем окне
    - `MessagesPane` теперь горизонтальный `JSplitPane`: сообщения ассемблера слева, ввод-вывод программы справа, с регулируемым разделителем
    - Кнопки «Clear» удалены из интерфейса; очистка доступна через контекстное меню (правый клик) соответствующей области
    - Заголовки «Messages» и «Run I/O» сохранены как подписи над областями
 - [x] При открытии текстового файла он по умолчанию открывается в режиме "Edit", а не "Execute"
    - Операция Open всегда переключает главную панель на вкладку «Edit», в том числе если файл уже открыт, а пользователь находится на вкладке «Execute»
    - Даже при включённой настройке «Assemble on open» (которая автоматически собирает файл и переключает на вкладку «Execute») после открытия приложение остаётся на вкладке «Edit»
 - [x] После выполения программы до конца действия Step (F7) и Go (F5) должны быть доступны, и перед запуском программы сбрасывать состояние - выполнять действие Reset (F12)
    - После завершения выполнения программы (статус TERMINATED) кнопки и пункты меню Step (F7) и Go (F5) остаются доступными
    - Логика сброса вынесена из `RunResetAction` в переиспользуемый статический метод `RunResetAction.performReset(VenusUI)`
    - Если программа завершилась и пользователь нажимает Step или Go, перед запуском автоматически выполняется Reset (сброс регистров/памяти/состояния и повторная сборка), затем запуск идёт с начала
